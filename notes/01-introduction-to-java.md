# Introduction to Java

- Java is 
    - developed by james gosling in 1995
    - programming language which is 
        - high level : 
        - object oriented : 
        - platform independent  
            - work on principle "Write Once, Run Anywhere" (WORA)
            - use JVM which runs on the machine and compiles java source code to byte code 
            - later byte code is converted to machine code, which run the program
            - so wherever jvm is present java can run regardless of platform and its configuration
            - this also make programs & software written in java portable and platform independent
    - inspired for C/C++ but removes it complexity, adds more security as everything run on safe sandbox environment and features for faster developer
 
- Bytecode is 
    - intermediate code which is generated by `javac` after successful compilation and stored with `.class file`

- Java is compiled to bytecode for portability, then interpreted and JIT-compiled by the JVM for speed.

## JDK, JRE and JVM relationship

1. Java Development Kit: 
    - its installed differently for every OS or platform so its platform dependent
    - required on machine where java is executed and additional tools are needed to develop the java software and has
        - compiler (javac) : check compile time errors and create byte code
        - debugger : lets you pause a running program, step through it line by line, and inspect variables and state to find bugs.
        - docs: tool that generates HTML API documentation from special /** ... */ comments in Java source code, using tags like @param, @return, and @throws.
        - other dev tools like:
            - `jar`: packages class files and resources into a JAR file.
            - `jshell`: interactive shell to run Java snippets without a full program.
            - `javap`: disassembles `.class` files to show bytecode.
            - `jdeps`: analyzes class and module dependencies.
            - `jlink`: builds a custom, minimal runtime image.
            - `jpackage`: packages an app into a native installer.
            - `jcmd`: sends diagnostic commands to a running JVM.
            - `jstack`: prints thread stack traces of a running JVM.
            - `jmap`: dumps heap memory information.
            - `jstat`: monitors JVM statistics such as GC and memory.
            - `jconsole`: GUI tool for monitoring a running JVM.
            - `jfr`: handles Java Flight Recorder profiling data.
            - `keytool` and `jarsigner`: manage keys and certificates, and sign JARs.
        - JRE

2. Java Runtime Environment:
    - is part of JDK but also available separately for only running already developed software in java
    - it has class libraries which provide built in & pre-implemented thing of java just modules, functions and API libs
    - JVM

3. Java Virtual Machine (JVM) loads and executes that bytecode with:
    1. Class loader: reads `.class` files into memory before execution begins.
    2. Memory areas: manage Java runtime data such as classes, objects, threads, and more.
    3. Execution engine:
        - JIT compiler: watches for frequently executed code (hot methods) and compiles it into native machine code while the program runs. That machine code is then run directly by the CPU, which is much faster.
        - Interpreter: reads each bytecode instruction and carries out its action one at a time. It starts quickly but runs slower.
    4. Garbage collector: removes unused parts of memory.

    So, only hot methods become machine code. The rest is run by the interpreter, which is already native machine code inside the JVM. So the CPU never runs your bytecode directly.

    > JDK has JRE, JRE has JDK

### Java edition
    - Java Standard Edition (Java SE): used for core Java development, such as desktop and console applications, and it provides the base language and core libraries.
    - Java Enterprise Edition (Java EE): used for large-scale enterprise and web applications, built on top of Java SE with APIs for servlets, databases, messaging, spring-boot and more. It is now called Jakarta EE.
    - Java Micro Edition (Java ME): used for applications on resource-limited devices, such as embedded systems, IoT devices, and older mobile phones.
